# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息；structured 在原文证据之上做受控 REGF 蜂巢结构解释，返回可达键值记录与缺口说明。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 每个可达键值一条，valueName 保留原值名（空名以 default 编码表示），type 保留 REG_* 类型，value 按声明类型表达，不能以 cell 顺序作为键值身份。每条记录含稳定 id（由来源、键路径、值名与键/值单元偏移派生，不使用数组下标）、keyPath、keyCellOffset、valueCellOffset、valueNameEncoding、inline、dataLocation 与来源 source，使来源位置可追溯。

结构化收件状态语义：
- `complete`：根可达范围内全部键值可确认且无缺口。
- `partial`：部分配置仍有来源依据并已输出为 records，同时 issues 列出可定位缺口（序列号不一致、索引越界、循环、计数不符等）；未决范围不被当作空键。
- `rejected`：根键或蜂巢整体无法解释，不输出记录，仅保留原文证据与问题说明。
issues 每条含 code、中文 message、可定位 location 与 scope；coverage 说明同步状态、遍历范围（root-reachable-only）、是否扫描空闲单元、是否恢复删除、是否展开环境变量及是否做凭据提取，后四者恒为 false。环境变量字符串（REG_EXPAND_SZ）只保留表达式，expanded 恒为 false。
